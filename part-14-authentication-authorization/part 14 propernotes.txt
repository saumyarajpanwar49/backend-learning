============================================================
1. AUTHENTICATION VS AUTHORIZATION
============================================================

1. CONCEPT

Authentication = WHO ARE YOU?
User ki identity verify karna.

Authorization = WHAT CAN YOU DO?
User ko kis action ki permission hai, ye check karna.

2. REAL-LIFE EXAMPLE

Bank:
Authentication = Verify karna ki tum account holder ho.
Authorization = Check karna ki tumhe money transfer karne ki permission hai.

3. HOW IT WORKS

User login -> Identity verify -> Authentication successful.
Protected action -> Permission check -> Allow/Deny.

4. CODE IMPLEMENTATION

if (user.role === "admin") {
    console.log("Access Granted");
}

5. IMPORTANT PROPERTIES

- Authentication: Identity verification.
- Authorization: Permission verification.
- Roles and permissions.
- Resource-level access.

6. SECURITY CONSIDERATIONS

Frontend ke role checks par trust mat karo.
Backend par permissions verify karo.

7. INDUSTRY BEST PRACTICES

Authentication aur Authorization separate rakho.
Principle of Least Privilege follow karo.

2. HTTP STATELESSNESS
============================================================

1. CONCEPT

HTTP stateless protocol hai.
Server automatically previous request remember nahi karta.

2. REAL-LIFE EXAMPLE

Har baar restaurant mein jaakar waiter ko apna naam batana.

3. HOW IT WORKS

Request 1: POST /login
Response: Login Successful.

Request 2: GET /profile
Server automatically nahi jaanta ki user kaun hai.

4. CODE IMPLEMENTATION

app.get("/profile", (req, res) => {
    res.send("Profile");
});

5. IMPORTANT PROPERTIES

- Independent requests.
- No automatic memory.
- Authentication state separately maintain hoti hai.

6. SECURITY CONSIDERATIONS

Client ki identity blindly trust mat karo.

7. INDUSTRY BEST PRACTICES

Sessions ya Tokens use karo.
Har protected request verify karo.

3. COOKIES
============================================================

1. CONCEPT

Cookie browser mein stored small data hota hai.
Browser matching requests ke saath cookie server ko bhejta hai.

2. REAL-LIFE EXAMPLE

Hotel ka access card jo tumhe baar-baar identity batane se bachata hai.

3. HOW IT WORKS

Server -> Set-Cookie header -> Browser stores cookie.
Next request -> Browser sends Cookie header.
Server -> Cookie verify karta hai.

4. CODE IMPLEMENTATION

npm install express cookie-parser

const cookieParser = require("cookie-parser");

app.use(cookieParser());

app.get("/login", (req, res) => {

    res.cookie("sessionId", "random-value", {
        httpOnly: true,
        secure: true,
        sameSite: "lax",
        maxAge: 3600000
    });

    res.send("Cookie Set");

});

app.get("/profile", (req, res) => {
    console.log(req.cookies.sessionId);
});

5. IMPORTANT PROPERTIES

- HttpOnly
- Secure
- SameSite
- Max-Age
- Expires
- Domain
- Path

6. SECURITY CONSIDERATIONS

Password cookie mein store mat karo.
HTTPS use karo.
Cookie-based authentication mein CSRF protection lagao.

7. INDUSTRY BEST PRACTICES

HttpOnly + Secure + suitable SameSite.
Random session identifiers use karo.

4. SESSIONS
============================================================

1. CONCEPT

Session server-side stored user authentication state hai.

Browser mein generally sirf Session ID store hoti hai.

2. REAL-LIFE EXAMPLE

Gym membership card.
Card number se system tumhara membership record find karta hai.

3. HOW IT WORKS

1. User login karta hai.
2. Server credentials verify karta hai.
3. Server session create karta hai.
4. Session database/store mein save hota hai.
5. Session ID cookie browser ko milti hai.
6. Next request mein Session ID server ko milti hai.
7. Server session find karke user identify karta hai.

FLOW:

Browser -> Session ID -> Server
Server -> Session Store -> User Details

4. CODE IMPLEMENTATION

npm install express-session

const session = require("express-session");

app.use(session({
    secret: process.env.SESSION_SECRET,
    resave: false,
    saveUninitialized: false,
    cookie: {
        httpOnly: true,
        secure: true,
        sameSite: "lax",
        maxAge: 3600000
    }
}));

app.post("/login", (req, res) => {

    req.session.userId = "123";

    res.send("Login Successful");

});

app.get("/profile", (req, res) => {

    if (!req.session.userId) {
        return res.send("Unauthorized");
    }

    res.send("Welcome User");

});

IMPORTANT:
Default MemoryStore production ke liye suitable nahi hai.
Redis ya database-backed session store use karo.

5. IMPORTANT PROPERTIES

- Session ID
- Session Store
- Session Expiry
- Session Regeneration
- Session Destruction

6. SECURITY CONSIDERATIONS

- Session fixation attack se protection.
- Session ID unpredictable honi chahiye.
- Login ke baad session regenerate karo.
- Logout par session destroy karo.

7. INDUSTRY BEST PRACTICES

Redis-based session store use kar sakte ho.
Idle timeout aur absolute timeout rakho.
Sensitive actions par session re-authentication consider karo.

5. PASSWORD HASHING - BCRYPT
============================================================

1. CONCEPT

Password ko database mein plain text store nahi karna chahiye.

Bcrypt password hashing algorithm hai.

IMPORTANT:
Hashing one-way process hai.
Encryption reversible hoti hai, hashing normally reversible nahi hoti.

2. REAL-LIFE EXAMPLE

Tumhare ghar ki key ka original duplicate store karne ke bajaye uska secure verification fingerprint store karna.

3. HOW IT WORKS

Registration:
Password -> Bcrypt + Salt -> Hash -> Database.

Login:
Entered Password + Stored Hash -> Compare -> Match/No Match.

4. CODE IMPLEMENTATION

npm install bcrypt

const bcrypt = require("bcrypt");

app.post("/register", async (req, res) => {

    const { password } = req.body;

    const hashedPassword = await bcrypt.hash(password, 12);

    // Save hashedPassword in database

    res.send("Registered");

});

LOGIN:

app.post("/login", async (req, res) => {

    const { password } = req.body;

    const isMatch = await bcrypt.compare(
        password,
        storedHash
    );

    if (!isMatch) {
        return res.status(401).send("Invalid Credentials");
    }

    res.send("Login Successful");

});

5. IMPORTANT PROPERTIES

- Salt: Random value added during hashing.
- Cost Factor: Computational difficulty.
- Hash: Stored password representation.
- Compare: Password verification.

6. SECURITY CONSIDERATIONS

- Plain passwords store mat karo.
- Password ko decrypt karne ki koshish mat karo.
- Login rate limiting lagao.
- bcrypt ki 72-byte input limit samjho.

7. INDUSTRY BEST PRACTICES

Argon2id generally preferred modern password hashing choice hai.
Bcrypt bhi widely used hai.
Appropriate cost factor benchmark karo.
Password hashes aur database credentials protect karo.

7. JWT - JSON WEB TOKEN
============================================================

1. CONCEPT

JWT ek compact token format hai jo claims ko securely represent karta hai.

JWT commonly stateless authentication mein use hota hai.

2. REAL-LIFE EXAMPLE

Airport boarding pass.
Usmein passenger aur flight ki information hoti hai.
Staff verify karta hai ki pass valid hai.

3. HOW IT WORKS

1. User login karta hai.
2. Server credentials verify karta hai.
3. Server JWT generate karta hai.
4. Client token store karta hai.
5. Client next request mein token bhejta hai.
6. Server signature aur expiry verify karta hai.

JWT STRUCTURE:

HEADER.PAYLOAD.SIGNATURE

HEADER:
Algorithm aur token type.

PAYLOAD:
User ID, role, expiry jaise claims.

SIGNATURE:
Token integrity verify karne ke liye.

4. CODE IMPLEMENTATION

npm install jsonwebtoken

const jwt = require("jsonwebtoken");

const token = jwt.sign(
    {
        userId: "123",
        role: "user"
    },
    process.env.JWT_SECRET,
    {
        expiresIn: "15m"
    }
);

VERIFY:

const decoded = jwt.verify(
    token,
    process.env.JWT_SECRET
);

console.log(decoded.userId);

5. IMPORTANT PROPERTIES

- Header
- Payload
- Signature
- Expiration (exp)
- Issuer (iss)
- Audience (aud)
- Subject (sub)
- Issued At (iat)

6. SECURITY CONSIDERATIONS

JWT payload normally Base64URL encoded hota hai, encrypted nahi.
Sensitive data payload mein mat rakho.
Signature verify kiye bina token trust mat karo.
Algorithm explicitly restrict karo.

7. INDUSTRY BEST PRACTICES

Short-lived access tokens use karo.
Secure token storage rakho.
Issuer, audience aur expiry validate karo.
Token revocation strategy plan karo.

10. AUTHENTICATION MIDDLEWARE
============================================================

1. CONCEPT

Middleware request aur response ke beech execute hone wala function hai.

Authentication Middleware check karta hai ki user authenticated hai ya nahi.

2. REAL-LIFE EXAMPLE

Office security guard jo entry se pehle ID check karta hai.

3. HOW IT WORKS

Request -> Middleware -> Verify Token -> Attach User -> Controller.

Invalid token -> 401 Unauthorized.

4. CODE IMPLEMENTATION

const authenticate = (req, res, next) => {

    const authHeader = req.headers.authorization;

    if (!authHeader) {
        return res.status(401).send("Unauthorized");
    }

    const token = authHeader.split(" ")[1];

    try {

        const decoded = jwt.verify(
            token,
            process.env.JWT_SECRET
        );

        req.user = decoded;

        next();

    } catch (error) {

        return res.status(401).send("Invalid Token");

    }

};

app.get("/profile", authenticate, (req, res) => {

    res.send(`Welcome ${req.user.userId}`);

});

5. IMPORTANT PROPERTIES

- req
- res
- next()
- Token verification
- Request user attachment

6. SECURITY CONSIDERATIONS

Missing, invalid aur expired tokens reject karo.
Unverified JWT payload use mat karo.

7. INDUSTRY BEST PRACTICES

Reusable authentication middleware.
Centralized error handling.
Consistent 401 responses.

const { OAuth2Client } = require("google-auth-library");

const client = new OAuth2Client(
    process.env.GOOGLE_CLIENT_ID

async function verifyGoogleToken(idToken) {

    const ticket = await client.verifyIdToken({
        idToken,
        audience: process.env.GOOGLE_CLIENT_ID
    });

        email: payload.email,

Short-lived access tokens.
