# CRUD OPERATIONS WITH EJS & SERVER-SIDE RENDERING
# COMPLETE NOTES (BASIC TO INDUSTRY LEVEL)

==================================================
1. WHAT IS SERVER-SIDE RENDERING (SSR)?
==================================================

SSR is a technique in which HTML is generated on the server and sent to the browser.

FLOW:

Browser
   |
HTTP Request
   |
Express Server
   |
Database (if required)
   |
EJS Template Rendering
   |
Generated HTML
   |
Browser

EXAMPLE:
When a user opens /read:
1. Browser sends GET request.
2. Express receives the request.
3. MongoDB returns users.
4. Express passes users to EJS.
5. EJS generates HTML.
6. Browser displays the page.

SSR VS CSR:

SSR:
- HTML is generated on the server.
- Browser receives ready-to-display HTML.
- EJS is commonly used with Express.

CSR:
- Browser generates or updates UI using JavaScript.
- Commonly used with React.

==================================================
2. WHAT IS EJS?
==================================================

EJS = Embedded JavaScript Templates.

EJS allows us to write JavaScript inside HTML and generate dynamic HTML pages.

INSTALLATION:

npm install express ejs mongoose

CONFIGURATION:

const express = require('express');
const app = express();

app.set('view engine', 'ejs');

Express automatically searches for EJS files inside the views folder.

PROJECT STRUCTURE:

project/
|
|-- node_modules/
|-- views/
|   |-- index.ejs
|   |-- create.ejs
|   |-- read.ejs
|   |-- edit.ejs
|   |
|   |-- partials/
|       |-- header.ejs
|       |-- footer.ejs
|
|-- public/
|   |-- stylesheets/
|   |   |-- style.css
|   |
|   |-- javascripts/
|   |   |-- script.js
|   |
|   |-- images/
|
|-- app.js
|-- usermodel.js
|-- package.json

IMPORTANT:
- views = EJS templates.
- public = Static files.
- node_modules = Installed packages.
- app.js = Main server file.
- usermodel.js = MongoDB model.

==================================================
3. EJS TAGS
==================================================

1. <%= %>

Outputs a value and HTML-escapes it.

Example:

<%= username %>

2. <%- %>

Outputs unescaped HTML.

Example:

<%- htmlContent %>

Use only with trusted HTML because untrusted content can cause XSS attacks.

3. <% %>

Executes JavaScript without displaying its result.

Example:

<% let age = 18; %>

4. <%# %>

EJS comment. Not included in generated HTML.

Example:

<%# This is a comment %>

5. INCLUDE

Includes another EJS file inside the current template.

Example:

<%- include('./partials/header') %>

Useful for reusable headers, footers and navigation bars.

==================================================
4. RENDERING EJS FILES
==================================================

Express uses res.render() to render an EJS template.

SYNTAX:

res.render('filename', { key: value });

EXAMPLE (app.js):

app.get('/', (req, res) => {
    res.render('index', {
        name: 'Saumyaraj'
    });
});

INSIDE index.ejs:

<h1>Welcome <%= name %></h1>

IMPORTANT RESPONSE METHODS:

res.send() = Sends a response.

res.render() = Renders EJS and sends HTML.

res.redirect() = Redirects the browser to another route.

res.status() = Sets HTTP status code.

==================================================
5. PASSING DATA FROM BACKEND TO EJS
==================================================

BACKEND:

app.get('/profile', (req, res) => {

    const user = {
        name: "Saumyaraj",
        age: 18
    };

    res.render('profile', { user });

});

profile.ejs:

<h1><%= user.name %></h1>
<p><%= user.age %></p>

PASSING ARRAYS:

BACKEND:

const users = ["Rahul", "Aman", "Saumyaraj"];

res.render('users', { users });

users.ejs:

<% users.forEach(user => { %>
    <h2><%= user %></h2>
<% }) %>

CONDITIONAL RENDERING:

<% if (users.length > 0) { %>

    <h1>Users Found</h1>

<% } else { %>

    <h1>No Users Found</h1>

<% } %>

IMPORTANT:
- Backend passes data using res.render().
- EJS receives the data using variable names.
- EJS can use loops and conditions to generate dynamic HTML.

==================================================
7. FORM HANDLING AND BODY PARSERS
==================================================

HTML forms send data to the Express server.

EXAMPLE HTML FORM:

<form action="/create" method="POST">

    <input type="text" name="name">

    <input type="email" name="email">

    <button type="submit">Create User</button>

</form>

BODY PARSERS:

app.use(express.json());

Parses incoming JSON request bodies.

app.use(express.urlencoded({ extended: true }));

Parses URL-encoded HTML form data.

IMPORTANT:
- req.body contains submitted form data.
- name attribute determines the key in req.body.
- Body parsers must be registered before routes that use req.body.
- Without the appropriate parser, req.body may be undefined.

EXAMPLE:

HTML:

<input type="text" name="username">

BACKEND:

let username = req.body.username;

IMPORTANT:

Schema = Structure and rules.

10. HOW HTML CONNECTS WITH CRUD OPERATIONS
==================================================

This is the most important connection between frontend and backend.

HTML uses:

1. <a href=""> for navigation and GET requests.
2. <form action=""> to specify the backend route.
3. method="GET" to retrieve pages/data.
4. method="POST" to submit form data.
5. name="" to identify submitted input values.
6. <button type="submit"> to submit a form.

CRUD CONNECTION:

CREATE:

<form action="/create" method="POST">

    <input type="text" name="name">
    <input type="email" name="email">

    <button type="submit">Create</button>

</form>

Backend:

app.post('/create', ...)

READ:

<a href="/read">Read Users</a>

Backend:

app.get('/read', ...)

UPDATE:

<a href="/edit/USER_ID">Edit User</a>

Backend:

app.get('/edit/:id', ...)

Update form:

<form action="/update/USER_ID" method="POST">

    <input type="text" name="name">

    <button type="submit">Update</button>

</form>

Backend:

app.post('/update/:id', ...)

DELETE:

<form action="/delete/USER_ID" method="POST">

    <button type="submit">Delete</button>

</form>

Backend:

app.post('/delete/:id', ...)

IMPORTANT:

- href triggers navigation.
- action specifies where the form submits data.
- method specifies the HTTP request method.
- name identifies the input field.
- :id is a dynamic route parameter.
- USER_ID above represents an actual user's MongoDB _id.

HTML forms natively support GET and POST.
For PUT, PATCH and DELETE form submissions, use method-override or JavaScript fetch.

11. COMPLETE CRUD OPERATIONS WITH EJS
==================================================

CRUD:

C = Create
R = Read
U = Update
D = Delete

Assume userModel is already imported.

------------------------------------------
A. CREATE OPERATION
------------------------------------------

STEP 1: CREATE FORM (create.ejs)

<form action="/create" method="POST">

    <input
        type="text"
        name="name"
        placeholder="Enter name"
        required
    >

    <input
        type="email"
        name="email"
        placeholder="Enter email"
        required
    >

    <input
        type="text"
        name="image"
        placeholder="Image URL"
    >

    <button type="submit">Create User</button>

</form>

STEP 2: EXPRESS ROUTE (app.js)

app.post('/create', async (req, res) => {

    let { name, email, image } = req.body;

    await userModel.create({
        name,
        email,
        image
    });

    res.redirect('/read');

});

EXPLANATION:

1. User fills the HTML form.
2. Form sends POST request to /create.
3. Express receives the data through req.body.
4. create() inserts a new document.
5. redirect() sends the browser to /read.

STEP 3: OPEN CREATE PAGE

app.get('/', (req, res) => {
    res.render('create');
});

IMPORTANT:
GET / opens the form.
POST /create saves the user.

------------------------------------------
B. READ OPERATION
------------------------------------------

STEP 1: EXPRESS ROUTE

app.get('/read', async (req, res) => {

    let users = await userModel.find();

    res.render('read', { users });

});

STEP 2: READ PAGE (read.ejs)

<% if (users.length > 0) { %>

    <% users.forEach(function(user) { %>

        <div>

            <h2><%= user.name %></h2>

            <p><%= user.email %></p>

            <img src="<%= user.image %>" alt="User image">

        </div>

    <% }) %>

<% } else { %>

    <h2>No Users Found</h2>

<% } %>

STEP 3: HTML LINK TO READ PAGE

<a href="/read">Read Users</a>

EXPLANATION:

1. User clicks Read Users.
2. Browser sends GET /read.
3. find() retrieves users from MongoDB.
4. res.render() passes users to read.ejs.
5. EJS loops through the users.
6. Browser displays all users.

------------------------------------------
C. UPDATE OPERATION
------------------------------------------

UPDATE HAS TWO MAIN STEPS:

1. Fetch existing user and open edit form.
2. Submit updated data and save it.

STEP 1: EDIT BUTTON IN read.ejs

<% users.forEach(function(user) { %>

    <h2><%= user.name %></h2>

    <a href="/edit/<%= user._id %>">
        Edit User
    </a>

<% }) %>

IMPORTANT:

- href sends a GET request.
- user._id identifies the selected user.
- :id receives this value in Express.

STEP 2: GET EDIT ROUTE (app.js)

app.get('/edit/:id', async (req, res) => {

    let user = await userModel.findById(req.params.id);

    if (!user) {
        return res.status(404).send('User not found');
    }

    res.render('edit', { user });

});

EXPLANATION:

- req.params.id gets the user's ID.
- findById() fetches that particular user.
- res.render() sends user data to edit.ejs.

STEP 3: EDIT FORM (edit.ejs)

<form action="/update/<%= user._id %>" method="POST">

    <input
        type="text"
        name="name"
        value="<%= user.name %>"
    >

    <input
        type="email"
        name="email"
        value="<%= user.email %>"
    >

    <input
        type="text"
        name="image"
        value="<%= user.image %>"
    >

    <button type="submit">Update User</button>

</form>

IMPORTANT:

value="<%= user.name %>"

Displays the existing user's name inside the input.

action="/update/<%= user._id %>"

Sends updated form data to the route containing that user's ID.

STEP 4: POST UPDATE ROUTE (app.js)

app.post('/update/:id', async (req, res) => {

    let { name, email, image } = req.body;

    await userModel.findByIdAndUpdate(
        req.params.id,
        {
            name,
            email,
            image
        },
        {
            runValidators: true
        }
    );

    res.redirect('/read');

});

EXPLANATION:

1. User changes input values.
2. Form sends POST /update/:id.
3. req.params.id identifies the user.
4. req.body contains updated values.
5. findByIdAndUpdate() updates MongoDB.
6. Browser redirects to /read.

IMPORTANT:

find() = Returns an array of matching documents.

findOne() = Returns one matching document or null.

findById() = Finds one document using _id.

findByIdAndUpdate() = Updates one document using _id.

------------------------------------------
D. DELETE OPERATION
------------------------------------------

STEP 1: DELETE FORM IN read.ejs

<% users.forEach(function(user) { %>

    <h2><%= user.name %></h2>

    <form action="/delete/<%= user._id %>" method="POST">

        <button type="submit">Delete User</button>

    </form>

<% }) %>

STEP 2: DELETE ROUTE (app.js)

app.post('/delete/:id', async (req, res) => {

    await userModel.findByIdAndDelete(req.params.id);

    res.redirect('/read');

});

EXPLANATION:

1. User clicks Delete User.
2. Form sends POST /delete/:id.
3. req.params.id identifies the document.
4. findByIdAndDelete() removes the document.
5. Browser redirects to /read.

IMPORTANT:
Never use a normal GET link to delete a database record.

==================================================
14. GET VS POST
==================================================

GET:
- Used to retrieve resources.
- Parameters can be passed through URL.
- Can be bookmarked.
- Should not modify database state.

POST:
- Used to submit data.
- Data is sent in request body.
- Commonly used for creating records.
- Also used for HTML form-based updates and deletions.

IMPORTANT:
HTTP also supports:

PUT = Replaces a resource.

PATCH = Partially updates a resource.

DELETE = Deletes a resource.

HTML forms natively support GET and POST only.

15. ERROR HANDLING AND VALIDATION
==================================================

Use try-catch to handle asynchronous database errors.

EXAMPLE:

app.post('/create', async (req, res) => {

    try {

        let { name, email, image } = req.body;

        await userModel.create({
            name,
            email,
            image
        });

        res.redirect('/read');

    } catch (error) {

        res.status(500).send(error.message);

    }

});

IMPORTANT VALIDATION:

1. Validate required input fields.
2. Validate email format.
3. Check whether a user exists before updating.
4. Handle invalid MongoDB ObjectIds.
5. Handle duplicate-key errors.
6. Handle database connection errors.
7. Return correct HTTP status codes.

COMMON STATUS CODES:

200 = OK

201 = Created

302 = Redirect

400 = Bad Request

401 = Unauthorized

403 = Forbidden

404 = Not Found

500 = Internal Server Error

==================================================
16. IMPORTANT SECURITY AND INDUSTRY PRACTICES
==================================================

1. Never use GET routes to modify or delete data.
2. Validate all incoming form data on the server.
3. Escape untrusted EJS output using <%= %>.
4. Avoid rendering untrusted HTML using <%- %>.
5. Use authentication before sensitive operations.
6. Use authorization to check whether a user can edit/delete a record.
7. Use environment variables for database credentials.
8. Protect state-changing forms against CSRF.
9. Use secure session and cookie settings.
10. Use rate limiting where appropriate.
11. Avoid exposing passwords and sensitive data.
12. Handle database errors properly.
13. Use proper HTTP status codes.
14. Use pagination for large user collections.
15. Add confirmation before destructive actions.
16. Use HTTPS in production.

17. COMPLETE APP.JS EXECUTION ORDER
==================================================

The following is the recommended basic structure.

const express = require('express');
const mongoose = require('mongoose');

const app = express();

const userModel = require('./usermodel');

// 1. BODY PARSERS
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// 2. STATIC FILES
app.use(express.static('public'));

// 3. EJS CONFIGURATION
app.set('view engine', 'ejs');

// 4. HOME PAGE
app.get('/', (req, res) => {
    res.render('create');
});

// 5. CREATE
app.post('/create', async (req, res) => {
    let { name, email, image } = req.body;

    await userModel.create({
        name,
        email,
        image
    });

    res.redirect('/read');
});

// 6. READ
app.get('/read', async (req, res) => {
    let users = await userModel.find();

    res.render('read', { users });
});

// 7. OPEN EDIT PAGE
app.get('/edit/:id', async (req, res) => {
    let user = await userModel.findById(req.params.id);

    if (!user) {
        return res.status(404).send('User not found');
    }

    res.render('edit', { user });
});

// 8. UPDATE
app.post('/update/:id', async (req, res) => {
    let { name, email, image } = req.body;

    await userModel.findByIdAndUpdate(
        req.params.id,
        { name, email, image },
        { runValidators: true }
    );

    res.redirect('/read');
});

// 9. DELETE
app.post('/delete/:id', async (req, res) => {
    await userModel.findByIdAndDelete(req.params.id);

    res.redirect('/read');
});

// 10. DATABASE CONNECTION AND SERVER START
mongoose.connect('mongodb://127.0.0.1:27017/mydatabase')
.then(() => {

    console.log('MongoDB Connected');

    app.listen(3000, () => {
        console.log('Server running on port 3000');
    });

})
.catch(err => console.log(err));

NOTE:
This is a basic learning example. Add centralized error handling, input validation, authentication and authorization before production use.
